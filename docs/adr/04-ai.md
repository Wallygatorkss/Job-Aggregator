# ADR 04 - Feature IA : matching profil <-> offre & generation de pitch

## Decision
La feature IA est un **moteur de matching et generation de lettre de motivation** execute localement, sans appel a un modele API tiers. Il :
1. Analyse le profil utilisateur (skills, experiences) et l'offre (titre, description, skills requises).
2. Calcule un score de pertinence (skills en commun, mots-cles detectes).
3. Genere une lettre de motivation personnalisee (1-2 paragraphes).
4. Alimente la table `offer_ai_data` (keywords, category, relevance_score, summary).

## Why
- Le PDF interdit d'externaliser l'IA a un modele API non controle, et impose **< 500 MB sur disque, < 5 s/offre, pas de fine-tuning au demarrage**.
- Une approche **rule-based + extraction lexicale** repond exactement a ces contraintes (0 MB de modele, < 100 ms/offre) et reste explicable au jury.
- Le code matching est ecrit en TypeScript pour rester dans le langage principal du backend.

## How
- Logique principale : [backend/src/services/offerAnalyzer.ts](../../backend/src/services/offerAnalyzer.ts).
- Etapes :
  1. Tokenisation du titre/description de l'offre et de la description du profil.
  2. Intersection des `skills` du profil avec les `offer_skill` et keywords detectes (agile, scrum, cloud, AWS, GCP, Azure, SaaS, startup...).
  3. Score `relevance_score` ∈ [0,1] = (skills_match + keyword_match) ponderes.
  4. Generation de pitch : template parametre par les matches trouves.
- Endpoint : utilise par la page `Ia.tsx` cote frontend et le flux CV (`/api/cv`).
- Feedback utilisateur : la table `ia_dislikes` (route `/api/ia-dislikes`) permet de marquer les recommandations non pertinentes pour mesurer la qualite.

## Limitations connues
- Pas de comprehension semantique : "developpeur front" et "ingenieur UI" sont vus comme differents si aucun mot-cle commun.
- Pas de detection de doublons d'offres (a ajouter en bonus avec une similarite Jaccard sur titre+entreprise).
- Score deterministe : pas d'apprentissage automatique sur les `ia_dislikes`.

## Evaluation
- Mesurable via `ia_dislikes / total_recommandations_vues` (taux de dislike).
- Objectif initial : < 30 % de dislike sur les 10 premieres recommandations affichees.

## Trade-off
- Approche legere = explicable, deterministe, gratuite, sans GPU. Mais qualite plafonnee par les regles ecrites.
- Pas de capture des synonymes ; pourrait etre ameliore par un modele d'embeddings local (sentence-transformers `all-MiniLM-L6-v2` ~80 MB).

## Alternative rejetee
**OpenAI / Anthropic via API HTTP** : violerait la consigne ("model API you do not control") et ajouterait latence + cout. Rejete.

**Modele d'embeddings local (sentence-transformers)** : meilleure qualite semantique mais ajoute Python + dependances ML (~200 MB) et complexifie l'image Docker. Reporte en backlog comme amelioration future.
