# ADR 06 - CI / qualite

## Decision
Pipeline GitHub Actions ([.github/workflows/ci.yml](../../.github/workflows/ci.yml)) declenche sur :
- push sur `main`
- pull request vers `main`

Tous les jobs tournent sur `runs-on: self-hosted` (exigence consigne).

## Jobs
| Job | Role | Detail |
|-----|------|--------|
| `build`  | Verifie que les services Docker se construisent | `docker compose build` |
| `lint`   | Lint TS frontend + backend | `npm run lint --if-present` (matrice) |
| `test`   | Tests automatises backend | `vitest run` avec MySQL 8.0 service |

## Couverture tests (minimum consigne respecte)
- **2 routes API** : `GET /api/skills/user` (requireAuth) et `GET /api/saved-offers` -> [tests/routes.test.ts](../../backend/tests/routes.test.ts).
- **1 fonction de normalisation** : `toEpochMs`, `toDate`, `toBigInt`, `toInt` de `offerIngestion.ts` -> [tests/normalize.test.ts](../../backend/tests/normalize.test.ts).

Resultat local : **17 tests passent**.

## Why
- **GitHub Actions** est exige par la consigne, integre nativement avec le repo.
- **Vitest** : zero-config, support TS natif via `tsx` deja present dans la stack, executable en moins d'une seconde.
- **supertest** : standard de facto pour tester des handlers Express en isolement, sans demarrer un vrai serveur.

## How
- `npm test` -> `vitest run` (mode CI, non interactif).
- Les tests de routes ne demarrent **pas** la base : ils valident le contrat HTTP (401 si pas de token, format du JWT genere). Cela rend la CI rapide et deterministe.
- Les tests de normalisation sont des tests unitaires purs (pas de I/O).

## Trade-off
- Pas de tests "happy path" qui appellent la DB ; la couverture metier reelle est plus faible mais le contrat de securite des routes est verifie.
- `self-hosted` requiert un runner provisionne ; impossible a executer sur GitHub-hosted sans modifier le workflow.

## Alternative rejetee
**Jest** : plus mature mais necessite `ts-jest` + config ESM/CJS pour TS. Rejete au profit de **Vitest** pour la simplicite et la vitesse.
